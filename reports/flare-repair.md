# Flare repaired: browser CPU and GPU inference pass

September 8, 2026. **The runtime correctness gate now passes for the tested SmolLM2-360M-Instruct Q8_0 bundle.** This is the actual Flare Rust/WASM engine generating answers in the browser. The good answers in the earlier failing runs came from the separate local llama.cpp reference.

## What was wrong

1. **Attention-weight layout mismatch.** Llama GGUF export interleaves Q/K rows for adjacent-pair rotary embeddings. Flare's rotary implementation expects split halves, matching the original Hugging Face weights. The loader now restores that layout for Llama GGUF f32 tensors and raw quantized weights, including separate raw-weight attachment. Other architectures and Safetensors retain their existing handling. The model file is unchanged.
2. **The last prompt token was processed twice.** Normal streaming prefilling consumed the entire prompt, then decoded its last token again at the next position. Both normal streaming entry points now prefill only the preceding tokens and process the final token once at its correct position. The existing healed-prefill path is retained.
3. **Invalid WebGPU attention pipeline.** The device requested the default 16,384 bytes of shared workgroup storage. The f16 attention pipeline required 16,416 bytes; the adapter exposed 32,768. WebGPU rejected the pipeline, and the unchecked readback returned zeros. Flare now requests the adapter's supported limit, rejects adapters below the attention family's minimum requirement, and checks command-validation errors before reading logits. Worker panic diagnostics reach the page rather than getting reduced to an unexplained `unreachable` error.

The earlier documentation fix is retained: a nested block-comment terminator in a Rust doc example made wasm-bindgen's generated JavaScript invalid.

## Limits and next work

This proves working browser inference with this Q8_0 model; it is not the planned 90% quality evaluation. The smoke prompts are small and synthetic, with expected answers known during development. Unknown-answer behavior, events, held-out entities, broad tokenizer coverage, Q4_0, long contexts, offline caching, and other GPU hardware remain to be evaluated. The diagnostic limits prompt plus response to 2,048 tokens; Flare's attention shaders have a fixed score-buffer capacity and should not be used beyond it.

The full conversational UI, Rust graph retrieval, graph/event dataset, MLX fine-tuning, export bundles, and four-way evaluation are still pending. No runtime replacement is needed to continue with the original architecture.
